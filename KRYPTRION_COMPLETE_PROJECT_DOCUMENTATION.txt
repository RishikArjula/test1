6.2 Two layers of PostgreSQL access

• Layer 1 — SQL privileges: Schema USAGE and table/column GRANT/REVOKE are checked before RLS. Missing privileges can raise permission denied.

• Layer 2 — RLS: When enabled and not bypassed, row policies further constrain rows and mutations; absence of an applicable policy is default-deny.

• service_role nuance: Supabase service_role commonly has BYPASSRLS, but BYPASSRLS does not override a revoked table privilege. A REVOKE ALL on a table can still make service_role receive permission denied.

• SECURITY DEFINER: Runs with function-owner privileges. The repository hardens selected functions'

owners/search_path; authorization inside such functions must use trusted caller identity/role checks rather than assuming current_user is the caller.

6.3 Important policy invariants

• No anon access to protected application data tables is defined by the migration policy model.

• Role-specific knowledge table SELECT is granted to authenticated, with per-table RLS limited to its matching approved role.

• service_role is explicitly revoked from all three knowledge tables in migration 12; do not assume a Python indexer using the service key can read them.

• Super Admin is excluded from raw operational records and gets aggregate knowledge metrics through a guarded RPC.

• audit_logs and account_activity have immutability/retention protections; service_role is revoked from audit_logs and has INSERT-only access to account_activity per repository SQL.

• incident_tasks UPDATE was hardened in migration 13: approved SOC Analyst or approved IT Operations assigned-role path only.

• Bootstrap state reads are restricted to approved Super Admin; a minimal status RPC avoids disclosing bootstrap PII.

7.2 Repository-described safeguards

• Copilot endpoints require Authorization Bearer JWT; Supabase getUser verifies token and the authoritative role/account status is loaded from user_profiles.

• Approved account status is required; client-supplied role headers/body are not trusted.

• Request validation includes non-empty prompt and maximum 2,000 characters; context types are allow-listed.

• README documents a 10 requests/minute/user rate limit and maximum 5 concurrent requests platform-wide.

• Retrieval is performed with request-scoped Supabase clients bound to the caller JWT, so RLS evaluates caller identity.

• Role scopes: SOC Analyst receives permitted triage and private notes; Security Engineer receives MITRE/detection context and read-only alerts with private notes redacted; IT Operations receives assigned tasks and linked alerts; Super Admin is denied raw operational records.

• Retrieved content is treated as untrusted and structurally delimited; deterministic citation IDs are attached; the system is instructed to report absence of evidence rather than fabricate it.

• Gemini key is server-only; generated output undergoes secret redaction; response is advisory and requires human verification.

• Copilot Markdown rendering avoids dangerouslySetInnerHTML and sanitizes unsafe links.
